Heli

Display for helis on FrSky radios with Ethos · Manual · Version 1.14.2 · As of 21.11.2026
German version: «Heli - Anleitung.pdf». The screenshots show the German display; with the language set to English the labels are in English (chapter 7, «Language»).

Heli is a widget for Ethos. It shows the heli's most important values on a whole screen, monitors five values with two adjustable thresholds each (orange, and red with sound), calls out the head speed during autorotation and keeps a list of flights on a second page. Display, menu and announcements are available in German and in English. New in 1.10.0: with the PC program Lua-Studio the display can be designed freely for each model (chapter 8, «Studio file from Lua-Studio»); without a Studio file the widget works exactly as in 1.9.1. New in 1.11.0: Lua-Studio format 2 with symbols, bold unit and decoration; without a Studio file the widget works as in 1.10.1. New in 1.12.0: the setting «Also with motor off» for each alarm (chapter 6), and after a model change Heli frees almost all of its memory.

Testing status: The widget has been tested in the Ethos simulator (Ethos 26.1.2; rotary encoder, swiping and PAGE also with Ethos 26.2.0), including long runs with random and extreme values: on 800 × 480 directly (X18RS simulator), recreated on 640 × 360, 480 × 320 and 480 × 272. On a real radio (X18RS, Ethos 26.2.0, Archer Plus SR10+ receiver, telemetry from a test device with 48 sensors), installation, automatic sensor search (8 fields assigned) and the display with live values worked on 20.11.2026. Not checked on the radio: each menu item individually, the announcements, the flight list with real flights, the rotary encoder and all other radios. New in 1.9.0 and so far only tested in the simulator: the compact view, the Governor field with ARMED/SAFE (Ethos 26.2, governor values injected in the simulator). On the radio (X18RS) the compact view has been checked, Governor and ARMED/SAFE not yet. New in 1.10.0 and so far only tested in the simulator (Ethos 26.2): the Studio file from Lua-Studio with .funke.lua, info file, note bar and the menu line «Studio file». Checked on the radio (X18RS, 20.11.2026): without a Studio file as before, a full Studio file in full screen without abort. Version 1.10.1 (Studio file sensors and info file on the radio, large Studio files in parts) is so far only tested in the simulator; .funke.lua, the compact view with a Studio file and English are still open on the radio. Version 1.11.0 (Lua-Studio format 2: symbols, bold unit, decoration) is only tested on the Mac test bench and in the simulator, ran on the radio (X18RS, 21.11.2026) with a full format 2 file in full screen without abort; the compact view, .funke.lua and English are still open there. Version 1.12.0 («Also with motor off», freeing memory) is tested on the Mac test bench and in the simulator, not yet on the radio. Counted on the Mac, a full format 2 file needs about 6,400 instructions per frame and the built-in display 6,400 to 7,500; this is within the format's target for drawing (below 10,000 since 21.11.2026, before 5,000). Not yet tested in flight. Please try it on the ground first and check the sensors (chapter 4).

1. What you need

  • A FrSky radio with Ethos (26.1 or later) and a colour screen. The display adapts to the screen size; chapter 11 lists the radios and what has been tested. The pictures in this manual show 800 × 480.
  • A computer with the FrSky Suite (FrSky's program for Ethos radios) and the radio's USB cable.
  • A heli with telemetry via the FrSky receiver. Meant for all helis: with any flybarless system, with normal FrSky sensors via FBUS/S.Port or with a telemetry ESC. Only «Profile / Rate» at the top right needs a system that reports the profiles; otherwise that spot stays empty.
  • The telemetry sensors have already been discovered in the model (Model › Telemetry › Discover new sensors).

2. Installing

You have received the file Heli-1.14.2-share.zip. The widget is put on the radio with the FrSky Suite; this way every file ends up in the right place.

  1. Unpack the ZIP for sharing. It contains this manual, a file LIES MICH.txt and the package Heli-1.14.2.zip. Do not unpack this package.
  2. Switch on the radio and connect it to the computer via USB. On the radio, choose Ethos Suite.
  3. On the computer, open the FrSky Suite and wait until it shows the radio.
  4. In the Suite, open Lua library, choose Install from local ZIP, select Heli-1.14.2.zip and click Install scripts. «Heli» then appears in the list of installed scripts.
  5. Disconnect the radio from the computer and restart it.
Important: The radio must be connected via USB before you click «Install scripts»; otherwise the Suite stops at «Start installing the script …». Do not delete an old heli folder on the radio beforehand: the Suite overwrites it, and it contains the flight list. Without the Suite it also works by hand: unpack Heli-1.14.2.zip, connect the radio as a USB drive and copy the folder heli including its subfolder audio into the radio's scripts folder (overwrite an existing folder, do not delete it). You then have scripts/heli/main.lua. Radios with an SD card: Ethos loads the scripts either from the internal memory or from the SD card, depending on a setting on the radio. The Suite follows it. By hand: copy to where the other Lua scripts are; if in doubt, to the SD card (SD:/scripts/heli). On an X18RS with Ethos 26.2.0, only the SD card loaded. The radio does not need the file ethos_lua_manifest.json.

3. Setting up the screen

  1. In the bar at the bottom, open Screens (Configure screens).
  2. Tap + at the top right. Swipe down in the list and choose the layout Full screen. If you want to keep the Ethos top and bottom bars, take the layout with one field and bars: the widget then draws the compact view by itself (chapter 5).
  3. Tap the empty field, open the list at Widget, swipe all the way down and choose Heli.

The widget's settings appear right below. Later you get back there via Screens › choose the screen › tap into the widget. Alarms, announcements and flight list need no further switch functions or special functions in the model; the widget does everything itself.

At the top the «Search» button, below it the groups. Tapping a group expands it; more groups follow when you swipe down.
An alarm group: On, orange threshold, red-with-sound threshold, repeat time.

4. Assigning and setting up sensors (once per model)

  1. Switch on the heli so that telemetry is running.
  2. In the line «Find sensors automatically», tap Search. A window «Searching …» appears and closes by itself when done. The widget fills all empty sensor fields it recognises; the IDs in brackets appear the next time you open the menu.
  3. Expand the group Sensors and check every field. Choose by hand whatever is empty or wrong. The search recognises FrSky sensors by their identifier (Application ID), not by their name; this way sensors with the same name from different devices are not mixed up. With flybarless systems, the voltage of the control board never counts as battery voltage and the BEC current never as battery current. Custom sensors without an identifier (e.g. «Headspeed», PID and rate profile) are found by name and unit. Next to the field name, the identifier and Physical ID are shown in brackets, e.g. «Battery voltage [0B50/0A]». If several sensors match, below it says «n sensors match, chosen: … – please check». The search can still be wrong.
  4. Governor (optional): If your flybarless system sends them, enable in its telemetry the values Governor State and Arming Flags. Heli reads them directly from the telemetry (AppID 0x5125 and 0x5122); no sensor needs to be created in Ethos.
  5. Group Battery: set Cells (e.g. 6 or 12), Capacity and Battery type (LiPo, LiHV or Li-Ion). The % display needs this if there is no % sensor. When you change the battery type, the thresholds of the cell alarm follow the new type (Li-Ion 3.10 / 3.00 V, otherwise 3.60 / 3.50 V) as long as they are still at the factory value; thresholds you have set yourself are kept. The line «Battery % from» shows whether a sensor or the widget's own estimate is used.
  6. Groups Alarm …: adapt the two thresholds to the heli or switch off individual monitors (chapter 6).
  7. Group RPM callout › Throttle channel: choose the channel on which the throttle goes to the heli. Without a throttle channel there is no RPM callout.
  8. Group Flight and motor switch: choose the switch you use to turn off the motor, and its «motor off» position (chapters 6 and 7). Without a switch the widget detects flights by the head speed, and there is no «Autorotation» announcement.
  9. Group Gauges: full scale: the value at which the gauges for head speed, current and ESC temperature are full.

The gauges run from bottom left over the top to bottom right; a quarter stays open at the bottom. A full gauge means: full-scale value reached (adjustable in the menu). MAX and LOW are measured values and start again with every battery. If a value is missing (no telemetry or no sensor assigned), -- is shown.

Governor and ARMED / SAFE

The Governor field shows the state of the flybarless governor: OFF, IDLE (grey), SPOOLUP, RECOVERY, BAILOUT, BYPASS (orange), ACTIVE (green), HOLD, AUTOROTATION (light blue) and LOST HEADSPEED (red with a frame, plus one tone, vibration and the announcement «Warning! Headspeed lost», at most every 10 s). «Lost headspeed» is the governor state «Fallback»: the governor has no headspeed signal (e.g. sensor or wire) and runs on the fallback throttle without speed control. The rotor does not necessarily slow down; still, land and check the headspeed sensor. Without governor telemetry it shows «--» and «--». The ARMED / SAFE pill comes from the arming flags of the flybarless system; without them it follows the motor switch (chapter 7).

Compact view (layout with top and bottom bars)

In the layout with bars, Ethos stays visible at the top (model name, radio battery) and at the bottom (clock, menu buttons). The widget then shows a narrow bar at the top with the flight time of the current flight, the ARMED / SAFE pill, profile / rate and the signal bars, below it the four gauges and eight fields: Governor, Cell, Used (tap = reset), BEC, Flight mode, Signal, Power (voltage × current) and Flights (tap = flight list). The widget detects the size by itself, no menu item is needed. The flight list looks the same in both views.

Tip: Give the flight modes in Ethos short names (e.g. «Normal», «Idle 1», «Hold»). Then the flight mode is shown large in the field. Long names are automatically written smaller.

6. Warnings, alarms and announcements

Monitoring: green, orange, red

Five values are monitored, each with two thresholds:

Orange (first threshold): only the display turns orange, i.e. the gauge or the number. No sound, no frame.
Red (second threshold): display and frame red, the header flashes red, plus warning tone, vibration and announcement.

As long as everything is fine, the monitored displays are green: the gauges for battery and ESC temperature and the numbers for cell, BEC and used capacity. A white number means: this value is not monitored («On» is off). The announcement first says what it is about, then the value, e.g. «ESC temperature, 85 degrees Celsius» or «Battery, 20 percent». It repeats at the set interval as long as the value is in the red range.

  • In every group: On, Orange from/below, Red + sound from/below, Repeat every, Also with motor off. If «On» is off, the value is not monitored at all (neither orange nor red).
  • Also with motor off (new in 1.12.0, on by default): if the tick is removed and the motor switch is in the «motor off» position, this alarm stays silent: no sound, no vibration, no announcement. The display still turns orange or red. As soon as the motor is on again, the alarm comes back. Without a motor switch the setting has no effect and the alarm always comes. «Lost headspeed» from the governor always comes.
  • Red only starts when the value has been beyond the threshold for one second in a row, and ends with some margin to the threshold. This way nothing flickers.
  • If several alarms are red, the announcements come one after the other. If the RPM callout or «Autorotation» is running, they take priority: then at most one alarm comes every 10 s.
  • Without a value (no sensor, no telemetry) a monitor stays silent.
Adapting the thresholds to your own heli: Under load the cell voltage drops briefly. If the alarm comes in normal flight, set the threshold lower. BEC and used capacity are off from the factory, because the suitable thresholds depend on the receiver voltage (5 V, 6 V, 7.4 V, 8.4 V) and on the battery.

RPM callout and «Autorotation»

RPM callout: If the throttle channel is at −25 % or lower and the rotor is still turning (above 300 RPM), the radio calls out the head speed every second. On the ground with the rotor stopped it stays silent. While the callout is running, a light blue dot lights up to the left of the flight count.

«Autorotation» announcement: If you turn off the motor with the motor switch while the rotor is turning, the radio says «Autorotation» and repeats it every 3 s until the rotor stops (head speed below 30 RPM) or you turn the motor back on. In between, the head speed is called out. For this, the motor switch must be selected in the menu under «Flight and motor switch»; with «Autorotation every» = 0 the announcement is off.

If the announcements lag behind: Speaking a four-digit number takes longer than one second. Then set RPM callout › Call out every to 2 s.

7. Operation

Battery in % and resetting used capacity

If the heli already sends the remaining charge in % (e.g. «Bat%»/«Fuel», in German Ethos also «Kraftstoff», or an ESC), the widget shows this value directly and does not calculate it itself. The automatic search assigns it; it can be changed by hand under Sensors › Battery %.

How the % display is produced when no % sensor is assigned:

  • When the battery is plugged in (2 s without load, «--» is shown during that time) the widget reads the cell voltage and uses the curve of the battery type to determine the starting value. Examples (guide values): LiPo 4.20 V = 100 %, 3.85 V = 55 %; LiHV 4.35 V = 100 %, 3.85 V = 38 %; Li-Ion 4.20 V = 100 %, 3.70 V = 47 %.
  • In flight it counts down with the used mAh. For this, Capacity and Cells under Battery must be correct.
  • If no capacity is entered, it shows the value from the cell voltage at rest; in flight this value stays fixed.
Caution, % sensor: If a sensor is assigned in the «Battery %» field (the automatic search fills it if there is one), the widget shows its value and does not calculate itself. If this sensor shows 100 % after plugging in a half-empty battery, clear the «Battery %» field.

Resetting used capacity (if the mAh do not start at 0 by themselves after a battery change):

  • Tap the RESET button in the «Used capacity» field and confirm the question with YES, RESET. Or
  • in the menu under Battery › Reset used capacity, press the «Set to 0 mAh» button. Or
  • choose Reset flight in Ethos; the widget then resets as well.

MAX and LOW also start again, and Battery % is determined anew from the voltage at rest. If the sensor itself counts from 0 again after plugging in, the widget notices this and you do not have to do anything.

Flights: motor switch, question and flight list

When a flight starts and ends

Group «Flight and motor switch» in the menu (factory settings, no switch yet).

Under Motor switch you choose the switch you use to turn off the motor, under Motor off position its position for «off» (up, middle or down). All other positions count as «motor on».

With motor switch:

  • Motor on starts a flight.
  • Motor off pauses the flight and asks «Flight finished?». YES, FINISHED completes the flight, it goes into the list. NO, JUST PAUSE leaves it open; at the next «motor on» the same flight continues.
  • If you turn the motor back on without answering (e.g. after an autorotation), the question disappears by itself and the flight continues.
  • A paused flight counts as finished when the battery has been unplugged for more than 30 s. It is also not lost when you switch off the radio. On page 2 you can tap the «paused» line, then the question comes again.
  • If the switch is already at «motor on» when the radio is switched on, the flight starts as soon as the rotor turns.

Without motor switch: The flight starts as soon as the head speed is above 500 RPM and ends 5 s after it has dropped below. There is then no question.

In both cases a flight only counts once it has lasted 30 s. Shorter runs (test on the ground) are discarded.

Question after «motor off».
Page 2 «Flights»: flight 11 is tapped, its values are on the left, at the bottom the button for deleting this flight.

The flight list (page 2)

  • Open: swipe left on the display, tap the flight count or turn the rotary encoder to the right. Back: swipe right, «BACK» or turn the rotary encoder to the left past the top flight.
  • On the right are the last 20 flights, the newest at the top, the current one with «live» or «paused». If they do not all fit, swipe up and down in the list (a scroll bar appears on the right).
  • Tap a flight: its values appear on the left: flight time, used capacity, highest head speed, highest current, highest ESC temperature, lowest cell and BEC voltage, battery at the end. Tapping the left field shows the newest flight again.
  • With the rotary encoder: turning right selects the next flight further down, turning left the next one further up; the list scrolls along. Deleting is done with the button at the bottom or via the menu (see «Without touch»).
  • Deleting a single flight (e.g. a short on and off that should not count): tap the flight, then at the bottom centre DELETE FLIGHT … and confirm the question. The flight count goes back by one and the later flights move up, the numbers stay without gaps. This also works with the current or paused flight: if you tap the paused one, «Flight finished?» comes again first (not when selected with the rotary encoder); after «NO, JUST PAUSE» the button appears. If you delete the current flight without a motor switch, a new one only starts again after the rotor has stopped.
  • CLEAR LIST empties the whole list after a question. The flight count is kept; it can be set by hand in the menu under «Display and flight count».

Flight count and list are saved per model on the radio (scripts/heli/daten/). From the display you get to the next Ethos screen by swiping left twice. On this screen the rotary encoder belongs to the widget: you do not switch to other Ethos screens with it. All other keys stay with Ethos and work as usual; PAGE takes you to the next screen.

Without touch (e.g. X14, X10, X12)

With the rotary encoder you page between display and flight list and select a flight as described above. Everything else is done via the widget's menu, group Flights without touch:

  • Page: «Display» or «Flights» switches between page 1 and page 2.
  • Select flight (0=latest): the number of the flight whose values are to be shown on the left. With 0 the top line of the list applies (current or newest flight).
  • Delete selected flight, Finish current flight (instead of the question «Flight finished?») and Clear flight list: one button each with a question. In the question, «CANCEL» is preselected. If the selected flight does not exist, a note appears and nothing is deleted.
  • Question: just pause closes the question «Flight finished?» on the page; the flight stays paused (like «NO, JUST PAUSE»).
  • You reset the used capacity in the group Battery › Reset used capacity.

Language

The display with the language set to English.

Under Display and flight count › Sprache / Language you choose same as radio, Deutsch or English. This applies to the display, the questions, the menu (after it is next opened) and the announcements of the alarms and of «Autorotation». Ethos speaks numbers and units in the radio's language.

The settings are saved with the model and apply only to this model. At the very top of the menu there are also the lines «Find sensors automatically» (chapter 4) and «Studio file» (next section). With a Studio file, its settings and limits apply (see below).

Studio file from Lua-Studio (new in 1.10.0, format 2 new in 1.11.0)

With the PC program Lua-Studio you design the display freely for each model and set settings and limits. Lua-Studio writes the file scripts/studio/ID.heli.lua to the radio, into the same storage the radio loads its scripts from (with an SD card usually SD:/scripts/studio/). The ID is the model name in which every character other than A–Z, a–z and 0–9 becomes _; an umlaut gives __ («Logo 700» becomes Logo_700). Lua-Studio does this itself. Heli reads the file when the model is loaded.

  • Without this file Heli works exactly as in 1.9.1, without any note. The menu shows «Studio file: none».
  • Own views: each view applies to exactly one window size (e.g. full screen 800 × 480 or compact view 784 × 316), at most two views per file. A view has up to 16 boxes («places»); for each one Lua-Studio sets the value, the style (number, ring, bar horizontal or vertical, trend, status such as Governor or ARMED/SAFE), title, range, colours and an extra line (MIN, MAX or Ø), at most two trends per view. Heli still draws the top bar itself. In full screen the view replaces page 1 only; you open the flight list as usual. For other window sizes Heli draws its built-in display.
  • Value adjustment: for each value the file can set factor and offset, unit, decimals and name. This applies in all boxes of the studio view, to the limits and to the head speed and alarm announcements. The built-in display (window size without a studio view, header, bar, flight list) still shows the sensor value.
  • Limits apply per value, even if it is not shown in any box. If a value is missing from the limits in the file, the factory limit applies (cell voltage according to the battery type). An alarm is only switched off if the file explicitly says so. If, for ESC temperature, battery %, cell voltage, BEC voltage or used capacity, the direction does not fit the value, the factory limit also applies, with a note. The file can also set limits for further sensors and channels: these alert with tone and vibration, without announcement, at most every 10 s.
  • If you change battery, limits or other settings in the menu on the radio, Heli writes this to its own file ID.heli.funke.lua. The Lua-Studio file stays unchanged, and so does the widget storage. Lua-Studio shows the differences and takes them over on request. The sensor assignment stays in the widget.
  • Menu › Studio file › Reset: the line shows the state (none, loaded, loaded with n errors, broken, too new). With a file, Reset asks «Back to Studio settings?» and after YES, RESET deletes your changes on the radio (the .funke.lua). Without a valid file it asks «Back to defaults?»: factory settings and limits, sensors and flights stay.
  • Notes: if the file is broken, made for a newer Heli version or contains invalid entries, a dark bar appears at the bottom for 8 seconds («Studio file broken - default», «Studio file too new - update the Lua» or «Studio file: n errors»), then an orange «!» at the top right until the next model change. A broken .funke.lua is discarded («Changes on the radio discarded»); the Studio file still applies. Heli always keeps running, if in doubt with the built-in display. What exactly is wrong is in the log (one line «Heli: Studio-Datei …» per error).
  • Format 2 (new in 1.11.0): Heli reads Studio files in format 1 and 2; format 1 files keep working unchanged. With format 2 a box can show a symbol at the top left in the colour of the value (the title then moves to the right) and the unit in bold at the top left instead of next to the value, or no unit at all. In addition there is decoration per view: freely placed symbols, texts, lines and frames, at most 24 per view. Lua-Studio offers the templates «Current look» and «With symbols» (each for 800 × 480 and 784 × 316). Symbols and decoration do not change any limit, announcement or alarm.
  • «Also with motor off» (new in 1.12.0): In Lua-Studio you can choose for each limit whether the alarm also comes with the motor switch «off» (yes by default). This applies to the five alarms and to the additional limits (sensors, channels). If you change the tick in the widget menu, it is stored in the file .funke.lua like the thresholds.
  • Symbol files: the symbols are greyscale images (PNG) in the folder scripts/studio/symbole/, named name_px.png (e.g. akku_64.png). Only Lua-Studio writes them; all Luas and models on the radio share the folder. A Studio file names at most 20 symbols. Heli loads them in small steps after a model change, so they appear a few frames later. If a symbol file is missing or broken, the box stays without a symbol and the bottom shows «Studio: n symbols missing» for 8 seconds, then the orange «!» at the top right.
  • File limits: value adjustments, limits and settings take up to 48 entries each; Heli discards further entries with a note.
  • For Lua-Studio, Heli writes the file ID.heli.info.json after every model change (model name, radio, sensor list, window sizes). Only Lua-Studio reads it; it is also written without a Studio file.

Copied by hand: is main.lua directly in scripts/heli/, on the drive from which the radio loads the scripts (with an SD card usually SD:/scripts, see chapter 2)? 10. Updating and removing

  • New version: install with the Suite exactly as in chapter 2. The Suite replaces the program and announcements; the folder daten with flight count and flight list is kept, as are your settings. By hand: overwrite the files in scripts/heli/ including the folder audio, leave the subfolder daten in place.
  • After updating from a version before 1.4, the new «Orange» threshold is set to match the previous red threshold, and the language is set to «same as radio» (change it under «Sprache / Language» if needed).
  • Upgrading from «Heli RF» (up to 1.12.0) to «Heli» 1.13.0: the widget is now called «Heli», folder scripts/heli. In every model select the widget again and set it up (the settings start from the factory values); re-transfer Studio files with Lua-Studio or rename them to ID.heli.lua. An old …helirf.lua is still read, with a note in the log. Flight count and flight list are taken over automatically from scripts/helirf/daten/; delete the old folder only after every model has been used once.
  • From 1.9.1 to 1.10.x, 1.11.0 and 1.12.0 all settings are kept. 1.12.0 saves in a new format (adding «Also with motor off», on everywhere after the update); going back to an older version, the factory settings apply there. Without a Studio file nothing changes in the operation; existing Studio files (format 1) keep working.
  • Removing: first remove the widget from the screen, then uninstall it in the Suite or delete the folder scripts/heli. The files ….heli.… in the folder scripts/studio belong to Lua-Studio; they do no harm and can be deleted by hand.
